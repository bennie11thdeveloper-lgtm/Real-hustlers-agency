Important distinction

You access each account using the email and password you choose when registering with that provider. This guide contains sign-in links, never passwords or secret API keys. Account access does not automatically mean the website integration is configured.

Never send passwords, verification codes, Flutterwave secret keys, Resend keys, Africa’s Talking keys, UploadThing tokens, or Supabase service-role keys in email or chat.

02 / OFFICIAL PROVIDER ACCOUNTS

Open each account securely

Use the official sign-in or registration page. Create each account in the agency’s legal/business name, keep owner access under the agency, and turn on multifactor authentication where available.

Supabase

supabase.com/dashboard

Create the agency project and manage its Postgres database, Authentication, Edge Functions, and one-time security setup. Select the agency project after sign-in.

UploadThing

uploadthing.com/dashboard

Create an app and a storage token. For applicant documents, enable Allow Overriding ACL; the site stores uploaded documents privately.

Flutterwave

app.flutterwave.com

Complete business verification and confirm your account can accept UGX payments and Uganda mobile money, including the intended MTN and Airtel options. Test in test mode before live payments.

Africa’s Talking

account.africastalking.com

Set up the account, obtain an API key, and confirm Uganda SMS access, sender rules, and credit. Use the sandbox username only with sandbox credentials.

Resend

resend.com

Verify an agency-owned sending domain, add the required domain DNS records, then create an API key and choose a verified sender address.

Account recovery: If you cannot sign in, use that provider’s “Forgot password?” link on its official portal. A provider’s password-reset link is not the same as the website editor’s admin-password reset.

03 / ONE-TIME WEBSITE ACTIVATION

Set up before launch

A developer or trusted technical administrator completes these initial deployment tasks once. Provider credentials go into the Supabase secret manager—not React code or the website editor.

1
Create a Supabase project

Copy the project URL and publishable/anon key into the site’s public deployment settings. Never use the service-role key in the browser.

2
Apply the two database migrations in order

Run 20261013000000_create_applications_and_payments.sql, then 20261013010000_add_site_content_editor.sql. They create the protected applicant/payment records and the admin-editable website copy.

3
Add server-side provider secrets

In the Supabase project, add APP_ORIGIN, APP_SITE_URL, FLW_SECRET_KEY, FLW_WEBHOOK_SECRET_HASH, UPLOADTHING_TOKEN, RESEND_API_KEY, RESEND_FROM_EMAIL, AT_API_KEY, AT_USERNAME, and optional AGENCY_NOTIFICATION_EMAIL.

4
Deploy the Supabase Edge Functions

Deploy submit-application, payment-status, uploadthing, and flutterwave-webhook. Configure Flutterwave’s charge.completed webhook to https://YOUR_PROJECT.supabase.co/functions/v1/flutterwave-webhook and enter the matching webhook secret hash.

5
Invite the agency owner as the first editor

In Supabase Authentication → Users, invite the owner’s email and complete the invitation. Add the exact user ID to public.site_admins once, using the SQL instruction in the project’s README. Do not grant access to unknown users.

6
Connect and test the public domain

Set the production domain as the app origin and authentication redirect. Check form submissions, private file uploads, SMS/email delivery, Flutterwave test checkout, signed webhook verification, and return-page status. Only then switch to approved live credentials.

Candidate fee: The current checkout is fixed at UGX 150,000. Publish the agency’s precise registration/paperwork service, fee, refund terms, privacy notice, and contact details. Check the fee and overseas-recruitment rules with qualified local counsel and licensing authorities before accepting candidate payments. A payment does not promise a job, visa, or employment.

04 / EVERYDAY CONTENT EDITING

Update the website without backend visits

After the initial setup is complete and your owner/editor account has been authorized, make ordinary website-copy updates in the website itself.

Open the Real Hustlers content editor → /admin
1
Go to the admin page

Visit your deployed address followed by /admin—for example, https://realhustlers.ug/admin. Bookmark this private sign-in page.

2
Sign in using your invited agency account

Use the email address and password from your owner invitation. Select “Forgot your password?” if necessary; follow the secure email link and set a new password on the admin page.

3
Edit the labeled fields

The editor groups text by site section. Change navigation, hero wording, job-title labels and descriptions, how-it-works steps, agency story, application-form labels/instructions, buttons, footer copy, and the terms link.

4
Save and review

Select Save changes, wait for the success message, then choose “View public site” or reload the public page. Published copy is stored in Supabase and loads from the site on visitor visits.

5
Keep account access controlled

Sign out on shared devices. Give admin access only to trusted editors. To add or remove editors, ask the technical administrator to update the authorized admin list—do not share one person’s password with the whole team.

Routine edits do not need: a code editor, an npm command, a database table editor, or access to the Supabase/hosting backend. They only need your website URL, admin login, and an internet connection.

The application or Save button is disabled

  • The public Supabase project may not have been configured or deployed.
  • Publish the real agency fee/refund terms page over HTTPS and enter its complete URL in **Payment Terms Url** in the editor. Save the content.
  • Do not use a placeholder or a terms link you have not reviewed.

Admin sign-in works, but the editor will not load

  • Ask your technical administrator to confirm both database migrations were applied and that your signed-in account was explicitly added to the admin list.
  • Try reloading the page and signing in again. Password recovery requires the deployed /admin URL to be on the allowed Supabase redirect list.

Payment or message did not arrive

  • Check the Flutterwave transaction dashboard. A browser return alone does not confirm payment; the verified webhook does.
  • Check SMS account credits and the applicant’s Ugandan number. Check Resend delivery logs and sender-domain verification.
  • Do not ask an applicant to pay a second time until checking the original transaction.
Security & privacy: Do not collect real applicant documents until the private UploadThing ACL is confirmed. Restrict staff access, keep provider secrets secret, and do not store passwords or applicant documents in the content editor.

Project setup details and the exact first-admin SQL are in the included README.md. For changes to the fee, integration behavior, or page structure, contact an authorized developer. This guide does not contain account passwords or secret API keys.
